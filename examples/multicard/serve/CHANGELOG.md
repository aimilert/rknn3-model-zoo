## 2026-09-20

### 🆕 默认端口 8080 → 18280；CORS 从 `*` 改成"默认一个都不放行"

**为什么**：用户问"把 8080 暴露出来有没有安全隐患"，随后要求"换成更安全的端口、注意
信息安全"（当场选的是**换端口 + 收紧 CORS**，没选共享令牌、没选 HTTP 层限流）。查下来
真正的洞不是"谁能连上"（`HOST` 默认 `0.0.0.0`，整个局域网本来就能连），而是
**`Access-Control-Allow-Origin: *` + 这个 API 不要凭据**：局域网里**任何人打开的任意网页**
都能在访客不知情的情况下驱动这块板卡（读 `/v1/system` 发起生成、用 `/v1/pool` 给的 key
把别人的对话 close 掉）。而演示页是**同源**的，那个 `*` 对正经用法一点用都没有。

**改法**：
- `--port` 默认 18280（`start_gateway.sh` 的 `PORT` 同步；所有 demo/验收脚本的 BASE 默认值
  一起改）。**端口不是安全控制**——同一局域网扫一遍就找到了——它只是把板卡从"默认端口
  那份名单"上挪开，配合下面那条一起看。
- `CORS_HEADERS` 常量（写死 `*`）换成 `cors_headers(allowed, origin)`，**默认返回空**；
  `--cors-origin` 显式给一个来源才回，且**精确匹配**（不做子串/通配），重启横幅里写明
  当前放行了谁。四个发响应的地方（`_json` / `OPTIONS` 预检 / `GET /demo` / SSE）全走它。
- 预检在没配置来源时只回一个空 204（不发 `Allow-Methods`/`Allow-Headers`）：浏览器拿不到
  ACAO，自己就把跨源请求拦了——这才是"不允许"该有的样子。
- 自检新增 19 条（`selftest_cors`）：**真起一个 HTTP 服务、真读响应头**，因为四处发响应的
  地方是各写各的，函数返回值对不代表线路上发出去的头对。变异体（还原成永远发 `*`）会红
  16 条。**换端口这件事不改帧协议**，后端二进制不用重编。

⚠️ 改端口**不是单向的**：同事的 SSH 隧道、cc-switch 的 Base URL、浏览器书签都得跟着改。

**上板**：`restart_gateway.sh` 带 `PORT=18280 CTX=32768 NSESSION=2` 重启后，`/health`
`sessions:2 / ctx_size:32768 / backend_alive:true`；**带 `Origin: http://evil.example`**
打 `/health` 与 `/demo` 都是一个 `Access-Control-*` 都没有，`OPTIONS` 预检 204 且不带
`Allow-*`；`:8080` 拒连。

### 🆕 演示页整页一屏：对话区吃掉剩余高度，资源块改成左右两栏

**症状**：用户报"对话框下面有很大的空余内容"——面板写死 `height:calc(50vh - 60px)`、
资源块按内容长，三块加起来不到一屏，屏幕上就是对话框下面一大片空白。

**改法**：整页变成一列 flex（`html,body{height:100%}` + `body{flex-direction:column}`），
标题与两条状态行 `flex:none`，**对话区 `flex:1 1 auto; min-height:0` 吃掉剩下的全部高度**，
资源块 `flex:0 1 auto` 按内容长、矮屏上由 `max-height:34vh` 封顶并在自己里面滚。
对话区行高改由 `grid-auto-rows:minmax(0,1fr)` 平分，面板不再有写死的高度。

**顺带把资源块自己压矮**（用户要"底部约占 1/5~1/4"）：原来上下两行块子要 376px，
1080p 上占 37%。现在 RK3588/热区/服务在左、四张卡在右（`.swrap` 两栏），高度变成
`max(左, 右)` 而不是两者相加 ⇒ **实测 249px**：1080p 上 25%、1440p 上 17%。
**一块内容没少、也没挤紧**，只是不再白占一行。窄屏（<1050px）退回上下两块。

**检查**（`page_check.js` 第 ⑩ 节，桩 DOM 没有排版引擎，所以解析 `<style>` 源码判高度关系）：
整页接成一屏 · 对话区 `flex:1` 且有 `min-height:0` · **任何块都不许用 vh 写死高度**
（就是那个坑）· 资源块封顶在 1/5~1/3 屏 · `.swrap` 两栏与 `.sg-host`/`.sg-cards` 的类名
两边对得上（JS 和 CSS 靠这三个字符串联系，谁单方面改名页面照样跑、只是长回 376px）。
解析前**先剥掉 CSS 注释**——注释里恰好写着 `calc(50vh - 60px)` 这种"以前的写法"。
四个变异体（面板写死 vh / 去掉封顶 / 去掉 `swrap` / 去掉窄屏媒体查询）都会红。

**上板实测**：`/demo` 取回来与工作区**逐字节相同**（md5 `5be0c976`）；1600×900 无头截图
整页恰好一屏、面板拉长、资源块在页脚占 **≈26%**（板上正跑 2 路，卡内存 93/93/93/95%）。
⚠️ `page_check.js` **要在有 node 的机器上跑**、用 `http://<板卡IP>:18280` 指过来——
板卡自己没装 node。

### 🆕 资源那一块挪到页脚、改成分块排版，并把它的开销压下来

**为什么**：用户提的两件事——设备资源使用情况放到网页**底部**、布局别太紧凑；以及
**尽量减少这个展示功能对硬件资源的占用**。它原来挤在标题正下方那一行里，第一眼看到的
是"内存 60%"而不是模型答了什么；而它每一拍都要网关读一遍 `/proc`、`/sys` 再向后端要一帧
STAT，这些都是**被看的那台机器**出的钱。

**改法（页侧）**：`#sys` 挪到对话区（`main#grid`）之后、`</body>` 之前，仍常驻可见
（"此刻板卡在干什么"任何时候都得看得见，只是不再跟对话抢地方）。排版换成两张网格：
上面 RK3588 / RK3588 热区 / 服务三块，下面**一张卡一块**——排成一行时四张卡看起来是
一条数据线，分块才数得出张数；块间 10px、块内行距 7px、条子撑满行宽，不再挤成一行。

**改法（省）**：
- **节奏**：生成中 2s、待机 6s（原来是固定 2s）；页面切到后台停轮询（原有的）；
  新一轮**刚开始生成**时立刻补一拍——待机档最长要等 6s 才看到卡忙起来，而那一帧
  恰恰是演示时最想看的。
- **不重画**：拿到的 doc `ts` 和上一次画的一样就**连 DOM 都不动**。网关侧有 1s 快照缓存，
  同一秒里的第二拍必然拿到同一份 —— 数字一个没变，`innerHTML` 重写却要整块重新排版一次。
  ⚠️ 判断里必须带 `ts != null`：应答里没有 `ts` 时 `undefined === undefined` 会让这一页
  **从此不再刷新**（冻在打开那一帧，屏幕上看着还挺正常）。
- **网关侧 `SYS_CACHE_S = 1.0`**：一秒内不管几个人来问 `/v1/system`，**只采一次**
  （采的时候持锁，后来的人等现成的）。看页面的人越多、被观测的机器越慢，这条就是为此。
  顺带让"同一秒里两份 doc 的 `ts` 相同"成为必然，页侧那道闸才真的省得下来。
- **热区表只问一次**：有哪些热区、各自叫什么，开机就定了（板卡上 7 个区 = 每拍 1 次 listdir
  + 7 次读 `type`），现在只缓存表，每拍只剩读温度那 7 次。只缓存**列成功**的结果。

**验证**：网关自检 **130 PASS / 0 FAIL**（新增 6 条钉快照缓存：同一秒只采一次、第二次拿到的是
**同一个对象**、`max_age=0` 强制重采、**过期必须重采**——只测"1 秒内不重采"的话，"缓存永不
过期"的写法照样全绿，而它在板上就是资源区冻住不动）；`page_check.js` 对桩网关
`sessions=2 @32768` 与 `sessions=4 @8192` 两种配置**全过**（新增：位置在 `#grid` 之后、
两个刷新档位、同一份 `ts` 不重画 / `ts` 变了必须重画 / 没有 `ts` 不许冻住、`sysWake`
真的补出那一拍）；本地对 8099 桩网关三次连问拿到**同一个 ts**、隔 1.3s 后再问换了新的。
**9 个变异体全被抓**（页侧 6：`send()` 不调 `sysWake` / 待机档写死 2s / 忘掉 `ts` 判空 /
永远不重画 / 四张卡那一行整块不画 / 位置判据反过来；网关侧 3：缓存永不过期 / 根本不缓存 /
采完不盖时间戳）——新加的断言不是空转。

**顺带修掉 `page_check.js` 自己的一处尾巴**：最后一节真的 `send()` 了一轮（要占一段对话），
而它收尾直接 `process.exit`；本地桩网关（`--idle-ttl 0` = 不回收）会被**永久**占着，同一个
桩网关连跑第二遍就在"增删窗口"那一节红——看着像页面坏了。现在走 `removePanel` 交还并等它
落地（交还是异步发的，不等就等于没交），**连跑两遍全绿、池子里干干净净**。

一句 `（来的时候池子里就占着 …）`，不进判定。变异体（把过滤去掉）在本机桩上复现出板上
**一模一样**的那个 FAIL，"改没改都绿"这种可能排除。改完板上重跑 **`===== 全部通过 =====`**

**顺带记一笔**：两边页面都从 `web-1` 起数 ⇒ 身份会撞车，网关当成**同一段对话**，对方的历史

话，身份得带上装载时刻。

### 🐞 资源条上板实测：两个只有真板卡能暴露的错（外加一个只在"有人同时看页面"时才犯的）

**症状 1**：页面上每张卡写着「内存 19.0 MB」，而同一时刻 `rknn-smi` 报 93% 占用。
**根因**：`RKNN3_QUERY_DEVICE_MEM_INFO` 那个结构体里有两组字段，**`sys_total/sys_free` 是
"本机侧的小块内存"**（板上实测 19905680 / 19564584 字节 ≈ 19 MB，占的是驱动/传输缓冲，
与模型放不放得下无关），**整卡内存是各 node 之和**——8 个 node × ~634 MB ≈ 5.06 GB/卡。
这句话 `--probe` 那段的注释里早就写过（"真正要看的是每个 node 的可用量"），取字段时没照做。
改法：`mem_total/mem_free` 改成 `Σ node.total / Σ node.free`（`node_min_free` 仍是"最紧那个"）。
改完对账：2 路 @32K ⇒ 0~2 号卡 92.4%、3 号卡 95.4%、最紧 node 13.25 MB —— 与早先记下的
`smi 93/95%`、`每卡 2 路` 那组数**逐项吻合**，这才叫取对了字段。

**为什么测试没拦住**：主机桩对设备内存一律回零，于是 `Σ node` 和 `sys_*` **都是 0**，
取哪个字段在主机上完全看不出来 ⇒ 桩改成**填一张确定的假表**，其中 `sys_*` 直接用板上量到的
那两个 19 MB 的数、node 数是 **3**（≠ 夹具的 2 段）。新增变异体 `stat_use_sys`（改回取 `sys_*`）
必须让 t12 变红——这类"静默显示假数"的缺陷只能靠夹具把它钉住。

**症状 2**：`/v1/system` 的 `busy_pct` 每隔几次从 `0.0` 变成 `None`，页面上在数字和 `—` 之间闪。
**根因**：利用率是"两次 STAT **答复**之差 ÷ 墙钟"，而 `STAT_WAIT` 当时钉的是 0.35s——板上
实测偶发答复会晚于它，超时的调用拿到的还是**上一份** doc（`now_us` 没动 ⇒ Δt=0 ⇒ 算不出比值）；
而每次采样又都无条件推进了窗口，导致下一次即使拿到新 doc，Δ 也只剩后半段。
**两处一起修**：`STAT_WAIT` 放到 1.0s（这条路径只服务 `/v1/system`，不在聊天请求的路上，
多等的 0.65s 不影响任何人）；同一份 doc 连着采两次时**既不推进窗口、也把上一次算出的百分比
原样给回去**（数据本身没变旧，`—` 要留给"真的没有值"）。这一条顺带把"多人同时看页面"
也修了：晚到的那个请求拿到的是同一个数，而不是 `—`，也不是一个被切短的窗口算出来的数。

**顺带**：`build_serve_native.sh` 的产物断言多了一条 `STAT `——装了旧 `main.cc` 就该编译不过检查。

**验证（真板卡，2 路 @32768）**：`/v1/system` 每卡 `mem_total = 5297191552`（5.06 GB）、
`mem_used_pct` = 92.4 / 92.4 / 92.4 / **95.4**、`node_num = 8`、`node_min_free` =
33.4 MB ×3 + **13.25 MB**（3 号卡就是最先撞墙的那张）；两轮对话后**四张卡 `run_calls` 都是 40**
——含 stage0，即"`session_run` 有两个调用点"那处修复在真机确认；`mem_age_s` 随推理刷新、
闲置时只是变老（KV 预分配，空闲不会再分配）。
**换上新网关（`STAT_WAIT=1.0` + 重复 doc 规则）后再量**：连着采 8 次（间隔 1.5s）
`busy_pct` **全是 `0.0`、一次 `None` 都没有**（修前这一组里会夹着 `None`），`stats_age_s`
0.0~0.7s 说明每次都拿到了新 doc；两轮对话时 `npu.busy_pct` 20.6、每卡 18.2~21.5，**停手 3 秒后
回到 `0.0`**——`0.0`（真的闲着）与 `—`（不知道）在这条路径上确实分得开。
主机侧：工作区版全绿、`HEAD` 版与 **10 个**变异体全在该失败处失败；网关自检 **124 PASS / 0 FAIL**；
`page_check.js` 对桩后端全过、对**真板卡**（2 路窗口）也全过。

### 🆕 演示页资源条：RK1828 每卡内存/NPU 忙时占比 + RK3588 内存/CPU/温度

**为什么**：板上跑着演示，屏幕上只有 tok/s。四张卡谁在干活、还剩多少余量、是不是快撑爆了，
全靠敲 `rknn-smi`——**而后端驻留时 `rknn-smi` 是取不到数的**（`Failed to initialize rknnsmi`：
设备同一时刻只认一个持有者）。所以这些数只能由**持有设备的那个进程**采，经帧协议报出来。

**三类数据的来路完全不同，别混**：

| 要看的 | 来路 | 边界 |
|---|---|---|
| RK3588 内存 / CPU / 负载 / 运行时长 | 网关自己读 `/proc/stat`、`/proc/meminfo`、`/proc/loadavg`、`/proc/uptime` | 与后端无关，后端死了这些照样有 |
| RK3588 温度 | 网关读 `/sys/class/thermal/thermal_zone*`，取最热的 3 个 | **只有 RK3588 的 7 个热区**（含它自己的 `npu-thermal`） |
| **RK1828 每卡内存** | `RKNN3_QUERY_DEVICE_MEM_INFO`，**后端**在推理之后顺手采 | 只有持设备者能查；查不到就保留旧值且**不更新采样时刻** |
| **RK1828 每卡"忙时占比"** | 后端累计每卡 `session_run` 的耗时 ÷ 墙钟 | **SDK 没有 NPU 利用率查询接口**，这是**算出来的** |
| 卡温 | —— | 卡是 PCIe 设备（`rkep`），**没有 hwmon、没有 thermal_zone**，拿不到 |

**改法**：

1. **后端新增 `STAT` 帧**（`main.cc`）：stdin 上一行 `STAT`（无载荷、无 rid）→
   `STAT <len>` + `<len 字节 JSON>`。载荷用 JSON 是因为这一帧是**嵌套**的（每卡一组数），
   排空格就得先定死字段序、以后加字段两边一起改。
2. **就地答复、不进调度队列**：排队的话它会被前面那条正在跑的长 decode 挡在后面——而
   "板卡正忙、想看看它在忙什么"恰恰是最需要它的时候。它只读原子量，零设备访问、零锁等待。
3. **快照在推理之后顺手采**（`record_stage_run_stat`）：`rknn3_query` 与 `rknn3_session_run`
   走同一条到设备的传输通道，SDK 没承诺并发安全 ⇒ 必须在这个卡的 `run_mutex` 里采，
   节流 2s（否则每轮 decode 多一次设备查询，实打实吃吞吐）。
4. **网关新增 `GET /v1/system`**：`{ts, host{...}, npu{busy_pct}, backend{alive,sessions,ctx_size,stats_age_s}, gateway{busy,bound,dead,waiting,uptime_s}}`。
5. **页面资源条**（`demo_4chat.html`）：CPU/内存/温度/负载 + 每卡 `NPU 忙时占比 / 内存 / 最紧 node 余量`，
   2s 轮询、页面切走就停。

⚠️ **加一种帧 = 后端与网关必须成对换**。这是同一个机制第二次咬人：网关的读线程对

|---|---|---|---|

### ⚠️ 演示页的"聚合 tok/s"口径改了：四路长度不齐时它会凭空变小

**症状**：一次真实四路（网页）屏幕上写着

| | 口径 | 用在哪 |

| 各路速率和 | `Σ(tok_i/el_i)`，**与单路基线同口径** | 横幅**主数**；**伸缩比只用它**（41.36/10.63 = 3.89×，用摊薄值会算出 1.45×） |

（它撤的就是刚印出来的伸缩比）。

### 🐞 NPU 空着，用户却在干等：第 N+1 段对话得等到某一段静默满 `IDLE_TTL`

**症状**：网页某一格 `158 tok · 100.9s · 1.57 tok/s`，而那一刻 **NPU 上一个请求都没在跑**。

**根因**：会话池只有一条回收阈值 `IDLE_TTL`（300s），且 `_reap_idle_locked` **只在 `acquire`
里被调用**。于是 N 段对话把 N 个会话**绑着不用**时，第 N+1 段对话要一直等到某一段**静默满 300s**
才拿得到会话——这中间 NPU 全空。板上实测（`page_repro.py`，四段对话静默 70–90s）：第 5 段
**排队 226.0s**，而它拿到会话的时刻正是 `web-1` 跨过 300s 的那一刻。`1.57 tok/s` 是**端到端**的
数——页面把这段排队也算进分母了，屏幕上分不出"模型慢"和"根本没轮到它"。

**修法**（两层，第二层只在第一层不够用时降下来）：

| 层 | 阈值 | 什么时候用 | 收几段 |
|---|---|---|---|
| 一（原有） | `IDLE_TTL` 300s | 只要有人问就一直在跑 | 所有静默超阈值的 |
| 二（新，`--contend-idle`） | 15s | **只有**一个空闲会话都找不到、这一轮非等不可 | **只收最闲的那一段** |

`idle_ttl=0` 仍是**总开关**：第二层绕过它就等于把"0 = 不回收"这条契约作废，而回归套件正是靠
它来证明自己真的在主动 `close`（不是碰巧被回收救了）。

**顺带把"等"变成可见的**：`X-KV-Reuse` 加 `wait=`、日志 `lease:` 行排过队就打 `排队 X.Xs`、
`/v1/pool` 报 `contend_idle_s`、页面排过队时行内显示 `⏳ 等待空闲会话…`、统计行拆成
`（其中排队 X.Xs，实际推理 Y.Ys）`、四格汇总栏加"有 N 路排过队 → 伸缩比不可引用"。
**不这么做就没法自证**：排队在 tok/s 上只表现为"变慢"，看不出异常，而那个 tok/s 恰恰是被排队污染的。

**板上实测（2026-09-18）**：

|---|---|---|
| 改前 | 70–90s | **排队 226.0s**（等满 `IDLE_TTL`） |
| 改后（在静默 0.5s 时敲） | 0.5s | 进队列，**15.4s** 拿到会话（`wait=15.0`） |
| 改后（在静默 24–42s 时敲） | >15s | **没进队列**，`wait=0.0`、TTFT 1.17s |

`reaped_total` 精确地 0→1→2（一次只收一段）；静默 41.8s 的两段**不被收**——只在真有人敲门时才动。

`[gateway] lease: session=0 reset=True sent=204/204 bytes (base=0) 排队 15.0s`。
