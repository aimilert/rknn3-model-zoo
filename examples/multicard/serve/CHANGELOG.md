## 2026-09-18

### 🐞 关思考时，网页某一格会出现满屏英文推理

**症状**：`demo_4chat.html` 的四个对话框里有一格不回答问题，而是吐一整屏
`<think>Thinking Process:…`，其他三格正常。**同一块板、同一份模型、同一个网关**。

**根因不在页面，在 prompt 的最后一个字节**：关思考一直靠 `/no_think` 这个**软**提示实现，
而"要组织语言"的题（`介绍一下杭州`、`写一首关于秋天的诗`）模型会先写一大段推理，正文里甚至
有一句 `* Constraint: /no_think (This means I should no…`——**它看见了提示、权衡了一下，然后
照开不误**。`max_tokens` 一截，`</think>` 来不及吐，`ThinkStripper` 只能按"宁可露标签也不
静默吞内容"把整段推理原样发给客户端。

**修法**：模型自己的 `tokenizer.chat_template` 里，`add_generation_prompt` 关思考时本来就会补
`<think>\n\n</think>\n\n`——补了它模型就是从 `</think>` 后面开始生成的，**结构上开不了 think 段**。
是我们在 `toolcalls.py` 主动把这个尾巴去掉了（理由是"改它会让之前所有吞吐数字失去可比性"），
现在补回来（`rkllm_gateway.THINK_OFF`）。

- ⚠️ **关思考下的 prompt 长度与 `completion_tokens` 都变了**：那 4 个 token 以前是模型**生成**
  出来又被摘掉的，现在是预填。**2026-09-18 之前量到的吞吐数字不能与之后的逐字节互比。**
- 补完之后关思考下与模板**逐字节一致**，`toolcalls.py` 顶部记的两处"刻意偏差"就此消掉，
  `known`（KV 记账）从"近似"变成精确。
- 回归测试在 `nothink_check.py` 第 4 节（用 256 而不是 96 当上限——96 下 think 段必然非空，
  测到的就只是"被截断了"）；`check_template.py` 多了一条"第二轮 prompt 以「第一轮 + 回复」
  为前缀"——那才是网关真正用的 KV 复用判据。
- **板上验收（2026-09-18）**：四路并发流式复现（`enable_thinking=false`、256 token，与网页
  同形态）**0/4 带 `<think>`**（改前 3/4）；`介绍一下杭州。` 直接回正文；全套件 8 段 rc=0、
  FAIL 0、非零 rc 0、traceback 0（伸缩 10.95 / 20.08(1.83×) / 37.65(3.44×) tok/s）；
  `page_check.js` 对真板卡 + 真模型全绿。关思考的 KV 复用照常（第二轮 base=258 / sent=132 /
  full=390）。⚠️ 改的是**网关进程**，必须重启（模型重载 ~240s）；旧件留
  `serve/bak_20260918_thinkoff/`。`（本次提交）`

### 🆕 演示页可以自己设输出上限 · `9804a41`

原先写死 256，而网关与后端都没这个数（终端版能从命令行给到 2000+）。页头加输入框，
值记在 `localStorage`，空/非数字/≤0 一律回落默认值（漏成 0 会被网关读成"用后端默认"，
屏幕上就成了假话）。方案文档 §9.12。

### 🐞 演示页统计行把 HTML 当纯文本渲了 · `8bba09e`

`setStat()` 写的是 `textContent`，而每个调用方都传 HTML（要让速率加粗）——于是页面上直接印出
字面的 `<b>11.63 tok/s</b>`。看起来只是"没那么粗"、不像坏了，藏了好几轮演示。顺手补了 `esc()`：
失败分支拼的是网关回的错误文本。方案文档 §9.12.4。

### 🐞 超过帧上限的载荷会把后端子进程打死 · `a54b259`（前一步 `d000d59`）

一个 3.4 MB 的请求就能让后端退出 → 四个会话全 dead → 之后每个请求在队列里干等到
`QUEUE_TIMEOUT` 才收到 503。改成**拒收**这一帧。（相关但不同的一条：1.6 MB 的请求体会让
**会话**成批死掉，成因仍未查清，见方案文档的已知限制。）

### 🆕 函数调用（Phase 1）：实现 + 板上验收 · `c1fd763` → `7b8f8a5`（文档 `c2c6f59`）

格式**不是猜的**，取自模型自己的 `tokenizer.chat_template`（XML，不是 Hermes JSON）。三处反直觉
的渲染规则见 `toolcalls.py` 顶部。**桩上全绿、板上第一遍就抓到一条真 FAIL**：回显助手轮丢了
`tool_calls`，而网关的前缀判据是**全有或全无** → 静默整段重算 469/469，不报错、答案也对。
方案文档 §9.9。

### 🐞 `restart_gateway.sh` 会杀掉执行它的那个 shell · `2345cf7`

`pkill -f` 的模式里带着二进制名，而 `INSTALL_DIR` 路径里也有那段字。现场像"程序自己崩了"。

### 🐞 prefill 分块按 `--bucket-size` 算而不是按输出张量 · `b13bbdb`

默认值下两种记法恰好相等，所以整套板卡测试全绿也证明不了它；板上复现要把 bucket 改成非 128

## 2026-09-16

### 🐞 上下文将满时静默清 KV · `1dde346`

改成显式拒这一轮（REJECT 帧）：后端拒过的那一轮一个 token 都没进 KV，会话**没死**，不能标死。
⚠️ 新后端会发 REJECT 帧，**旧网关的读线程不认这个 tag、不消费 payload，整条流错位**——
后端与网关是一对，不能只换一半。

### 🐞 一帧 ERR 会打死整个网关 · `5c167f5`

ERR 被按 DELTA 解析 → 读线程死 → 之后全 503。与上一条是同一个"未知 tag 不消费"的机制。
