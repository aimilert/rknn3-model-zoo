# 模型裁剪与多设备协同部署说明

## 背景
由于 **RK1820** 等设备的内存资源有限，在部署大规模多模态模型时需要进行适当裁剪，以保证在嵌入式平台上的可用性与推理效率。

## 模型裁剪策略
1. **vision部分**  
   - 在 RK1820 上，由于内存宝贵，将部分算子（op）迁移至RK3588或其他设备的 CPU 上实现。这样既能保留视觉特征提取的完整性，又能避免因资源瓶颈导致的llm上下文不够。
   - 注意如果想要llm有较长的上下文或者vision较大分辨率，则一定要开启vision裁剪模型。

2. **完整模型模式（无裁剪）**  
   - 如果是 RK1828 等内存更大的设备，则可直接使用完整模型。  
   - 在使用 Python 导出时，仅需添加以下参数即可启用完整模式：  
     ```bash
     python export_rknn.py --no_prune_mode
     ```
   - 如果需要调整视觉模型的分辨率，可以使用**--img_size**参数。
     注意：分辨率必须是 28 的倍数。
     ```bash
     python export_vision.py --img_h 448 --img_w 448
     ```

## C++ 部署支持
在 C++ 推理代码中，已经实现了对不同模型格式的自动识别逻辑：  
- 无需修改任何代码，即可兼容裁剪版与完整版模型；  
- 通过内部检测机制，自动选择对应的推理路径。
